# Live sweep #15 — does an inverse pair return you to where you were?

Fourteen passes asked "is this right?". Pass 14's lesson was that the
productive move is performing an ordinary chore end to end. Pass 15 takes that
one step further: run the operations that claim to REVERSE each other, because
an inverse pair has a ground truth no self-consistency check can fake — the
earlier state itself.

## The pairs that hold

| pair | result |
|---|---|
| `restore` to a lineage point | **byte-identical**, hash-verified by the tool itself |
| `duplicate` → edit the copy | original untouched — no aliasing |
| `move` A→B→A | back to start, both manifests correct (fixed in pass 14) |
| `resize` 1000→2000→1000 | byte-identical … and that was the disguise |

## The disguise

`resize` up and back came back BYTE-IDENTICAL. It looked like the strongest
pass of the four. It was the fault.

Checking the INTERMEDIATE state — the thing a round trip never shows you:

| layer | stored as | geometry at 2000×2000 | style |
|---|---|---|---|
| `bg_auto` | `x/y/width/height` | 1000 → **2000** ✓ | — |
| `bg` | `pos:[…]` | **1000, unchanged** ✗ | — |
| `head` | `pos:[…]` | **unchanged** ✗ | font 92→184 ✓ |
| `rule` | `pos:[…]` | **unchanged** ✗ | stroke 6→12 ✓ |
| `card` | `pos:[…]` | **unchanged** ✗ | radius 14→28 ✓ |

Reported: `layers_scaled: 6`. In pixels, on a 2000×2000 canvas, the navy
background covered `x 0–996, y 0–996` — the top-left quarter, cream showing
through the rest.

The round trip passed because `pos` was never touched in either direction. **A
round trip cannot see a fault that cancels itself.**

## Chasing it found the worse one

`pos` is shorthand PENDING EXPANSION — the finalize pass deletes it once it has
expanded one — but a plain primitive authored with `pos` is persisted with it
intact, and every MUTATION reads `x/y/width/height`. So:

    edit_layer {op:"update", layer_id:"card", props:{y:800}}
      pos: [80,540,400,220]  gains a SIBLING  y: 800
      inspect reports y=800 (and w:0, h:0)
      the renderer draws it at y=540, where it always was
      the tool and the inspector both report success

The most-used op on the surface, silently doing nothing.

Folded on READ, not at each mutation site: `readYAML` already self-heals a
malformed `layers` container there, several call sites already branch on both
forms, and autoplace already deletes `pos` once it has expanded one. Teaching
every mover about `pos` is precisely how the second form got missed to begin
with.

## Then the same species, one layer up

If a stored field can shadow the flat one that authors it, `pos` cannot be the
only case. Text layers keep words in `content:{type,value}` and typography in
`style:{}`. Rendering a layer that holds BOTH forms settles which wins:

| sent to `update` | stored canonical | what renders |
|---|---|---|
| `text: "FLAT"` | `content.value: CANON` | **CANON** |
| `font_size: 90` | `style.font_size: 40` | **40** |
| `size: 90` | `style.font_size: 40` | **40** |
| `color: "#EE0000"` | `style.color: #111111` | **#111111** |

"Change this headline", "make it bigger", "make it red" — three of the commonest
edits anyone makes — all returned `success: true` and changed nothing. This one
is far wider than the `pos` fault: only 3 of 278 designs persist `pos`, but
essentially every design stores text canonically.

Flat aliases are now routed into the canonical field, but only where one exists
to shadow them — a layer with no `style` reads a flat size correctly today, so
nothing is touched and no style block is invented on a rect.

## Backward compatibility

The `pos` fold changes every design read, so it got pass 13's treatment:
**276/276 diagnose clean**, 30/30 render. (39 first-run failures were my own
loop bursting the server — all 39 passed on retry with pacing. The instrument,
not the build.)

## Verified live, in pixels

    card moved to y=800   ink y 800–999          ✓ (was 540)
    resize to 2000        navy covers 0–1996     ✓ (was 0–996)

28 faults, 20 commits. The method that found these two: **compare two things
that must agree, and when they do, check the state BETWEEN them.** An inverse
pair is the cheapest such comparison — and the one time it agreed perfectly was
the one time something was badly wrong.
