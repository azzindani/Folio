# Live sweep #18 — auditing the door the MODEL walks through

Seventeen passes audited what the engine DOES. Nobody had audited what the guide
SAYS. `get_engine_guide` is Folio's instruction manual, and §0.4 makes surfacing
guidance the engine's job — so a hint that names a door which doesn't exist is
the deepest door fault there is: every blind-model design built from it is
wrong before the engine sees it.

88,051 characters across 15 sections, checked mechanically.

## What holds

| claim | result |
|---|---|
| 37 distinct `tool(op:)` references | **all exist** (checked against dispatch.ts) |
| 44 layer/preset `type:` names | **all expand** |
| every documented preset field, per preset | **all painted** |
| "a WIDE box is an expensive box" | **true, well calibrated** |

That last one is a causal claim the guide calls "the single most common way a
landscape slide goes wrong", so it is worth stating that it checks out.
Identical content, only the box width changing:

    700 -> 303px tall · 900 -> 381 · 1200 -> 485 · 1600 -> 632 · 1920 -> 749

2.7× wider box, 2.5× taller content. Exactly as warned.

## The fault

The guide's preset picker says **"a newsletter / bulletin → newsletter"**, the
height table gives it `1.10× W`, and the prose describes it — "bordered masthead
+ lead + a masonry of section boxes + footer". It names **not one field**,
anywhere in 88k characters. Same for `mindmap`, `value_list`, `ribbon_cards`.

They take `items`. The only multi-section shape the guide teaches anywhere is
`blocks`. So a model following the guide:

    add_layers {type:"newsletter", title, subtitle, blocks:[…], footer}
      -> success: true
      -> 4 of 7 content strings gone
      -> 326px rendered: a masthead and nothing else

    add_layers {type:"newsletter", …, items:[…]}      (undocumented)
      -> 8/8, 614px

An unknown preset name is rejected cleanly (`Invalid layer.type`), so this is
not a typo class — the preset is real, accepts the layer, and silently discards
the content. The dominant failure class this project already knows, reached
through the guide instead of through a tool.

Fixed: a worked example for each of the four, plus the alias table
(bulletin→newsletter, flyer→event, metric→stat, plans→pricing, compare→versus,
steps→list, roadmap→timeline, infographic→sections) so a model landing on an
alias knows whose fields to use. **Every claim was verified against the running
engine before being written** — 47 sentinels across 4 shapes and 8 aliases, all
painted, none lost.

## Four times my own instrument produced the finding

Worth recording, because it was the majority of the work:

1. `pattern` and `svg` looked like broken types — they are a FILL type and an
   EXPORT format; my regex matched `type:` inside nested objects.
2. `versus` and `sections` looked like they dropped documented fields — I had
   hoisted `label` out of `rows:[{label,a,b}]` and invented `heading` as a
   sibling when the guide teaches `{kind:"heading"}`.
3. The first field-survival run reported **all 43 fields kept** — it grepped the
   raw YAML, which contains `_spec`, the block that RECORDS what was authored.
   A dropped field still matched. That false ALL-CLEAN is the dangerous one; the
   real result only appeared after stripping `_spec`.
4. The preset height table looked 2× wrong for five rows — but the harness fed
   `blocks` to presets that read `items`, so several of those numbers measured
   an empty preset. **Not reported as a finding: my measurement was confounded
   and I could not separate a stale number from a bad probe.**

## And two in the fix itself

The first guide edit used unescaped backticks inside a template literal and
**broke `guide.ts`, which every module imports** — the whole suite went red. And
the drift test took three tries: anchored on the preset NAME it passed with the
example gutted (the alias table mentions the name too), then a fixed-width
window bled into the next example, which also says `items:`. Bounded at the
following `{type:"` now, and mutation-verified.

## Also removed

A personal handle shipped as the `author` slot DEFAULT of builtin template
345-project-card-poster, so rendering it credited one person on someone else's
poster. Neutral placeholder now. A repo-wide scan found no other personal-name
usage — the remaining 33 hits are the repository's own address, which the clone
commands, update check and image pull need.
